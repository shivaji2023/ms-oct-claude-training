        Optional<User> user = userRepository.findByEmail(email);
        boolean ok = passwordEncoder.matches(password,
  user.map(User::getPasswordHash).orElse(dummyHash));

  **6. [A07] The token validity check is a stub that always returns true; expiry
  is only enforced by accident**
  - **Where:** `JwtUtil.java:55-57` `isTokenValid()` and
  `JwtAuthFilter.java:33-34`
  - **Correction to the README:** expired tokens are not actually accepted. jjwt
  0.12.5 `parseSignedClaims` (called from `extractUserId`) throws
  `ExpiredJwtException` / `SignatureException`.
  - **The real problems:**
    - The check does nothing.
    - The filter has no try/catch, so a bad token causes an unhandled exception
  and an empty 403.
    - A stale token in the header breaks the permitAll `/api/auth/login` and
  `/register` endpoints, because the filter runs on every path.
    - Any refactor that drops `extractUserId` (for example caching claims)
  silently turns this into full acceptance of expired tokens.
  - **Impact:** expiry protection rests on a side effect and could disappear
  without anyone noticing; today it already causes a login denial-of-service for
  clients holding expired tokens.
  - **Fix:**
    ```java
    public boolean isTokenValid(String token) {
        try { Jwts.parser().verifyWith(key).build().parseSignedClaims(token);
  return true; }
        catch (JwtException | IllegalArgumentException e) { return false; }
    }
    ```
    In the filter, catch `JwtException` and continue without authentication.
  Better still, parse once, return `Optional<Long>`, and skip the filter for
  `/api/auth/**` via `shouldNotFilter`.

  **7. [A07 / A04 Insecure Design] No input validation and no password policy**
  - **Where:** `AuthController.java:21,27` (no `@Valid`) and `:32,35`;
  `AuthService.java:25`
  - **Impact:**
    - Users can register with a one-character password (`@NotBlank` is ignored),

    - Add `@Valid` to both `@RequestBody` parameters.
    - Add `@NotBlank @Email @Size(max=254)` on email and `@Size(min=12, max=72)`

    - Add a `MethodArgumentNotValidException` handler that returns 400;

    - Optionally, check new passwords against a breached-password list.
